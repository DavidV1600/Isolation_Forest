
\section{Implementation}
%==============================================================================

This section describes the implementation details of the \texttt{isotree} library \cite{isotree}, a high-performance C++ library developed by Cortes that provides unified implementations of all the isolation forest variants discussed in this paper. The library offers Python, R, and C++ interfaces, and serves as the basis for our experimental evaluation.

\subsection{Models defined}
%==============================================================================
\begin{itemize}
    \item \textbf{iForest}: Original Isolation Forest
    \item \textbf{EIF}: Extended Isolation Forest
    \item \textbf{SCiForest}: Split-Criterion Isolation Forest
    \item \textbf{FCF}: Fair-Cut Forest
\end{itemize}

\subsection{Multi-threading}

The library employs OpenMP for parallelism at two levels:

\begin{algorithm}[t]
\caption{Tree-level Parallelism}
\label{alg:tree-parallel}
\DontPrintSemicolon
\KwData{dataset $X$, number of trees $t$, sample size $s$}
\KwResult{forest $\mathcal{F}$}
\medskip
\For{$i = 1$ \textbf{to} $t$ \textbf{in parallel}}{
    $X_s \gets$ sample($X$, $s$)\;
    $\mathcal{F}[i] \gets$ \texttt{build\_tree}($X_s$)\;
}
\Return $\mathcal{F}$
\end{algorithm}

Each tree is built independently, allowing a very strong parallel construction.

\begin{algorithm}[t]
\caption{Prediction Parallelism}
\label{alg:pred-parallel}
\DontPrintSemicolon
\KwData{observations $X$, forest $\mathcal{F}$}
\KwResult{anomaly scores $S$}
\medskip
\For{$i = 1$ \textbf{to} $n$ \textbf{in parallel}}{
    $S[i] \gets$ \texttt{score\_observation}($X[i]$, $\mathcal{F}$)\;
}
\Return $S$
\end{algorithm}

Predictions for different observations are computed in parallel.

\subsection{Optimizations}

The library supports:
\begin{itemize}
    \item \textbf{Cache-friendly layouts}: Flat vector storage
    \item \textbf{Contiguous memory}: Improved cache locality
\end{itemize}

\subsection{Data Structures}
%==============================================================================

The library uses two main node structures for storing splits.


\begin{lstlisting}[language=C++,basicstyle=\ttfamily\small,frame=single,caption={Standard node structure for IF},label={lst:isotree-struct}]
typedef struct IsoTree {
    ColType  col_type;           // Numeric, Categorical, or NotUsed
    size_t   col_num;            // Column index for split
    double   num_split;          // Split threshold (numeric)
    std::vector<char> cat_split; // Bitmap for categorical splits
    int      chosen_cat;         // Selected category
    size_t   tree_left;          // Index to left child
    size_t   tree_right;         // Index to right child
    double   pct_tree_left;      // Fraction going left
    double   score;              // Depth/score at node
    double   range_low;          // Range bounds for penalization
    double   range_high;
    double   remainder;          // For distance calculations
} IsoTree;
\end{lstlisting}

\begin{lstlisting}[language=C++,basicstyle=\ttfamily\small,frame=single,caption={Hyperplane node for EIF/FCF},label={lst:isohplane-struct}]
typedef struct IsoHPlane {
    std::vector<size_t>   col_num;   // Multiple columns
    std::vector<ColType>  col_type;  // Type per column
    std::vector<double>   coef;      // Linear combination coeffs
    std::vector<double>   mean;      // Standardization means
    std::vector<double>   fill_val;  // Missing value handling
    std::vector<std::vector<double>> cat_coef; // Categorical coeffs
    
    double   split_point;            // Threshold on combination
    size_t   hplane_left;            // Left child index
    size_t   hplane_right;           // Right child index
    double   score;
    double   range_low, range_high;
    double   remainder;
} IsoHPlane;
\end{lstlisting}



The forest structures (\texttt{IsoForest} and \texttt{ExtIsoForest}) contain vectors of trees/hyperplanes along with metadata such as the scoring metric, expected average depth, and original sample size.

Trees are stored as \textbf{flat vectors} rather than pointer-based nodes for cache efficiency, easy serialization, thread safety, and memory locality.

\begin{algorithm}[t]
\caption{Tree Traversal}
\label{alg:traversal}
\DontPrintSemicolon
\KwData{point $x$, tree $T$}
\KwResult{isolation depth $h$}
\medskip
$\text{curr} \gets 0$ \tcp*{Root node}
\While{$T[\text{curr}]$ is not terminal}{
    \eIf{$x[T[\text{curr}].\text{col}] \leq T[\text{curr}].\text{split}$}{
        $\text{curr} \gets T[\text{curr}].\text{left}$\;
    }{
        $\text{curr} \gets T[\text{curr}].\text{right}$\;
    }
}
\Return $T[\text{curr}].\text{depth}$
\end{algorithm}
